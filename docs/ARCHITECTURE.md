# 架构与实现边界

## 模块

- `core/Memory.kt`：UTF-8 上界预算、无丢失消息分段、左右／日期解析、相邻重叠建议、引用 ID 校验、备份密码学、HTML 转义。
- `app/Data.kt`：Room 实体、DAO、Repository；UI 不直接编写 SQL。
- `ImportOcr.kt`：串行复制与去重、下采样、EXIF 方向、Bundled 中文 OCR；识别待人工确认。
- `LocalAi.kt`：单引擎互斥、CPU、后台初始化、流式生成、取消和资源释放；模型安装候选先验证，再替换原文件。
- `MemoryWorker.kt`：原文分页、稳定批次 ID、原子保存依赖、持久化进度、递归日／周／月／年合并。
- `AppViewModel.kt`：异步用例与状态；`Ui.kt`：中文 Compose 界面；`MainActivity.kt`：生命周期与应用锁。
- `Security.kt`：Keystore 密钥包装；`BackupExport.kt`：认证加密备份、恢复校验与 PDF / HTML / PNG。

## 原文与依赖

Message 同时保存 originalText、当前 text、版本、发送者、可空日期时间、原图 ID、顺序和人工确认状态。编辑前写 MessageRevision。摘要的 sourceIds 保存完整原文 ID，SummaryDependency 对所有祖先保持直接来源边，因此编辑消息能够直接标记各级相关摘要“待更新”；已确认事件重新变为待核实。原文不因摘要被覆盖或自动清除。

任务创建时 TaskMessage 固定消息集合与版本。读取 40 条原文后按日期与预算分段。已完成摘要以稳定 ID 去重，页处理完成才推进 processed 检查点；重启后可从最后完成页继续。任务原文被编辑或删除时停止，要求重新整理相应日期，避免将错版本数据当作最新内容。

合并阶段先按日、ISO 周、月、年分组；组内如果过长继续按预算递归合并。中间合并层使用负 level，仅最终日／周／月／年节点使用正 level；parentIds 记录层级，sourceIds 保留完整原文，eventIds 保留用户事件索引。递归无法收敛会报错，禁止无限循环或超上下文。任务默认串行，所有 AI 调用共享 Mutex。

这是可恢复编排代码，不代表实际模型已经完成长历史性能验收。WorkManager 的系统执行时间限制、设备省电策略和进程终止仍可能中断运行；UI 可继续检查点。年度精选首先读取已生成月度索引，选取已确认事件／收藏，再按原文逐章生成；不一次性生成数万字。

## 预算

总上下文 4096，模型输出上限 640，模板安全空间 768。普通文本采用 UTF-8 字节数上界，单批资料 2200 上界，再对完整提示执行 `requireFits`。这会比真实 tokenizer 保守，中文每批可用字符数较少，但不以汉字计数冒充 tokenizer。未来若 LiteRT-LM 暴露匹配模型的直接编码接口，应替换计数器，并继续保留完整提示与输出预留检查。

## 备份和恢复

备份版本 1，固定数据表与图片资源 ZIP，经 PBKDF2-HMAC-SHA256（随机 16 字节盐、210000 次）派生 AES-256 密钥，再采用随机 12 字节 IV 的 AES-GCM；格式魔数参与 AAD。密码和完整性校验失败时不写数据库。

模型及本机 Keystore 密钥不导出。恢复使用本机新密钥，验证路径白名单、文件数量、解压量、版本、表结构，先暂存文件，再在 Room 事务中重建数据；失败清理本次复制的文件。禁止路径穿越。外部分享的明文文件不具备备份加密保护。

## 已知需要改进的部分

备份暂为内存实现，128 MB 上限不适合大型图库；所有消息的 UI Flow 暂未使用 Paging。OCR 气泡合并依赖人工操作，屏幕中心或不完整日期不做确定性猜测。全文关键词检索是 SQLite LIKE，不是向量检索。模型引用检查无法替代事实审核。数据库目前首次 schema 版本为 1，没有历史版本可迁移；升级时必须新增显式 Migration，禁止 destructive migration。
